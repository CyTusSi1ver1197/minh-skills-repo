# Style, depth and follow-ups

## Style rules

- **Plain words first, term second:** "a list that keeps items in order — called a *queue*".
- **One new idea per sentence;** one running example throughout.
- **Short paragraphs** (≤ 4 sentences). Tables for comparisons, lists for steps.
- **Bold** a key term only on first appearance. Expand acronyms on first use.
- **Accurate over impressive.** Flag uncertain, version-specific or disputed
  points. Don't invent APIs, numbers or sources; point to official docs for
  details that change.
- **Match the learner.** If they show more knowledge, skip ahead; if lost, go
  back one layer with a simpler example, and note the change in the checkpoint.
- **Respond in the learner's language.**

## Depth

| Depth | Content | Delivery |
|---|---|---|
| overview | Steps 1–4, short Step 8, recap only | one reply |
| working (default) | all 10 steps | one stage per reply |
| expert | all 10 + edge cases, internals, performance in Step 5 | one stage per reply |

## Follow-up questions

1. Re-read the checkpoint.
2. Answer the specific question with the same running example.
3. Say where the answer sits on the Step 4 map (which node / link).
4. If it adds a new term or node, add it to the checkpoint.

## Context hygiene

- Don't paste large files into the answer; quote only the lines needed.
- Don't repeat earlier stages; refer to them by step number.
- If the conversation was compacted or you're unsure what was covered,
  trust the checkpoint, not recollection.
